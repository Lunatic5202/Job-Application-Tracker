# Security Policy

## Reporting a vulnerability

Do not disclose security vulnerabilities in a public issue, discussion, or pull request.

If GitHub private vulnerability reporting is enabled for this repository, use **Security → Report a vulnerability**. Otherwise, contact the repository maintainer privately through the contact options on the maintainer's GitHub profile. Include the affected version or commit, impact, reproduction steps, and relevant proof-of-concept details. Do not include real credentials, personal data, or production records.

## Response expectations

Reports will be reviewed as project activity and time permit. No response or remediation timeline is guaranteed. Please allow reasonable time for investigation and coordinated disclosure before sharing details publicly.

## Safe testing

- Test only systems and accounts you own or have explicit permission to assess.
- Do not access, modify, or retain other people's data.
- Do not perform denial-of-service, destructive, or privacy-invasive testing.
- Do not publish exploit details while a report is under investigation.

## Supported versions

Unless a release or maintenance notice says otherwise, security fixes are considered for the current default branch. Older releases may not receive backports.
